# ShopMate Architecture / 架构图

This Mermaid source renders on GitHub and remains editable.

```mermaid
flowchart TD
    Client[浏览器 / 手机] --> Tunnel[ngrok HTTPS 临时入口]
    Tunnel --> Caddy[Caddy 8080 / Basic Auth]
    Caddy -->|SSE 请求; 拒绝公开 /api/secure| API[FastAPI + Uvicorn 8000]
    API --> Guard[Day26 429/503 限流 + 请求超时]
    Guard --> Graph[LangGraph 规则式工作流]
    Graph --> Classify{意图分类}
    Classify -->|商品| Product[商品/价格/库存工具]
    Classify -->|政策| Policy[读取权威政策 Markdown]
    Classify -->|订单| Order[订单工具: 匿名拒绝]
    Classify -->|含糊| Clarify[澄清]
    Product --> Verify[答案与来源校验]
    Policy --> Verify
    Order --> Verify
    Verify --> SSE[SSE: retrieval / answer_delta / complete]
    Product --> SQLite[(SQLite 业务库)]
    Order --> SQLite
    Policy --> Corpus[(30 份合成 Markdown)]
    Boot[Day24 init / 迁移] --> Vectors[(PostgreSQL 17 + pgvector 30x512)]
    Boot --> LocalIndex[(本地 chunks.npz)]
    Probe[/health/ready] --> Vectors
    Probe --> SQLite
    Probe --> LocalIndex
    Auth[本机 Day23 安全 API] --> Sessions[(SQLite sessions.db)]
    Auth --> SQLite
```

## What is and is not on the live path

- **Runtime live answer**: `src/shopmate_agent/shopmate_graph.py` runs deterministic rules; policies use `answer_quality.policy_evidence(...)` reading `data/knowledge/policies/*.md`, product data are from SQLite, and anonymous order requests receive a safe no-evidence response. Verified answers stream in chunks from `stream_api.py`.
- **Embedding and vector store**: `data/index/chunks_meta.json` records `BAAI/bge-small-zh-v1.5`, exact revision `7999e1d3359715c523056ef9478215996d62a620`, and 30 chunks/512 dimensions. Day24 imports their embeddings to pgvector, persisted in a Docker volume. **Current customer response paths do not perform online pgvector retrieval.**
- **Security**: Caddy on 8080 authenticates only demonstration visitors; the private API under `/api/secure/*` is blocked from that public proxy, while the direct local App API still uses Day23 bearer-token and ownership checks. Do not mistake preview Basic Auth for real user authentication.
- **Liveness/readiness**: `/health/live` means process responds; `/health/ready` tests SQLite business/session data, local vectors and pgvector. Never put secrets in public responses.
- **Performance**: one Uvicorn worker has in-process rate/concurrency controls. Scaling to multiple workers requires a **shared** rate limiter; the current 20-concurrency test produced 36 overload 503 responses from 40 attempts.

## Corpus sources

`data/knowledge/products/` (20 files) + `data/knowledge/faqs/` (5) + `data/knowledge/policies/` (5) = **30 synthetic Markdown documents**. Each has `doc_id`, `version`, `source`, and `updated_at` frontmatter. Generated by `scripts/seed_demo_data.py`; not scraped, not real merchant policies, and not production data.

Evaluation: `eval/day27/dev.json` is the 7-case developer/ablation set; `eval/day27/holdout.json` is a frozen 20-case holdout (not a model training set). `reports/day27/holdout.json` includes the 17/20 automatic result and 3 failure IDs. Dataset overlap is tested in `tests/test_day27_eval.py`.
